# Project Plan: Generating Quantum-Jump Trajectories with a Conditional GRU-MDN

## Problem Statement

This project will test whether a deep-learning model can learn the statistical behavior of quantum trajectories generated by Monte Carlo wave-function simulations in QuTiP.

The main observable is the normalized collective spin polarization,

```text
s_z(t) = <S_z(t)> / N
```

where `N` is the number of two-level particles. The model should generate new `s_z(t)` trajectories that are statistically similar to unseen QuTiP trajectories.

A second goal is to test whether a model conditioned on system size `N` can generalize between different values of `N`, and possibly extrapolate modestly to slightly larger systems.

## Model Choice and Motivation

The proposed model is a conditional GRU with a Mixture Density Network output, abbreviated as a conditional GRU-MDN.

This model is appropriate because the data are stochastic time sequences. The GRU stores information about the trajectory history, while the MDN predicts a probability distribution for the next trajectory increment instead of a single deterministic value.

A deterministic recurrent model trained with mean-squared error would tend to predict averaged, overly smooth trajectories. The MDN output is better suited for stochastic quantum trajectories because it can represent multiple possible future increments.

The GRU-MDN is also a practical choice for a university project because it is simpler than diffusion models or neural stochastic differential equations, but still captures sequential memory and randomness.

## Data Generation Plan

Generate hundreds of QuTiP trajectories for several system sizes, for example:

```text
N = 8, 10, 12, 14, 16, 18
200-500 trajectories per N
140 time points per trajectory
```

Initially, keep the physical parameters fixed, such as `wx/wc` and `gamma0/gamma1D`, and vary only `N`. Later, the same framework can be extended to multiple parameter values.

The processed dataset should be stored in one file:

```text
data/processed/trajectories.npz
```

with arrays:

```python
sz             # shape: [num_trajectories, 140]
N              # shape: [num_trajectories]
omega_ratio    # wx/wc
gamma_ratio    # gamma0/gamma1D
```

Only observables and metadata are needed for this project. Wavefunctions should not be saved for ML training because they are much larger than necessary.

## Model Architecture

For each trajectory, define:

```text
s_t = <S_z(t)> / N
```

At each time step, the input vector is:

```text
x_t = [s_t, t/T, 1/N, wx/wc, gamma0/gamma1D]
```

The target is the next increment:

```text
delta_s_t = s_(t+1) - s_t
```

A suitable first architecture is:

```text
Input sequence: [batch, 139, 5]
Two-layer GRU, hidden size 64
Linear layer: 64 -> 64
ReLU activation
MDN output layer: 3K values
K = 5 Gaussian mixture components
```

For each time step, the MDN outputs:

```text
K mixture weights
K means
K standard deviations
```

These define the distribution:

```text
p(delta_s_t | history) = sum_k pi_k * Normal(mu_k, sigma_k^2)
```

## Training Procedure

Each complete trajectory is one training sample. The 140 time points are not independent samples.

For a trajectory with 140 time points:

```text
Input shape per trajectory:  [139, 5]
Target shape per trajectory: [139]
```

With batch size 32:

```text
Batch input shape:  [32, 139, 5]
Batch target shape: [32, 139]
```

During training, the model receives the real previous value `s_t` and predicts the distribution of `delta_s_t`. The loss is the negative log-likelihood of the observed increment under the predicted Gaussian mixture.

During generation:

1. Start from the known initial value `s_0`.
2. Predict the Gaussian mixture for `delta_s_t`.
3. Sample one increment from the mixture.
4. Compute `s_(t+1) = s_t + delta_s_t`.
5. Feed the generated value back into the GRU.
6. Repeat until the full trajectory is generated.

Generated values should be kept within the physical interval:

```text
-1 <= s_t <= 1
```

## Evaluation Plan

The model should be evaluated by comparing generated ensembles with held-out QuTiP ensembles. The goal is not to reproduce one exact trajectory, but to reproduce the correct statistical behavior.

Important comparisons:

- Mean trajectory over the ensemble
- Variance over trajectories as a function of time
- Histograms of `s_z` at selected times
- Final-value distribution
- Temporal autocorrelation
- Switching or residence-time statistics, if visible in the data

Useful baselines:

- Randomly replaying stored training trajectories
- A GRU with a single Gaussian output instead of a mixture output

These baselines will show whether the GRU-MDN is doing more than memorizing examples or producing averaged dynamics.

## Generalization Across N

First, test generation at a fixed system size:

```text
Train/validation/test split at N = 18
70% training
15% validation
15% testing
```

Then test interpolation across system sizes:

```text
Train: N = 8, 10, 12, 14, 18
Test:  N = 16
```

This checks whether the model learns meaningful dependence on `N` rather than simply memorizing trajectories from each size.

After that, test limited extrapolation while QuTiP ground truth is still available:

```text
Train: N = 8, 10, 12, 14, 16
Test:  N = 18
```

Only after these tests should the model be used to generate trajectories for slightly larger values such as `N = 20`. Such results should be described as extrapolation, not as a replacement for exact simulation.

## Assumptions and Limitations

This project assumes that hundreds of trajectories can be generated with QuTiP for each selected value of `N`.

The first version should focus on `s_z(t)` only. Additional observables, such as collective emission or jump counts, can be added later if needed.

The model is a statistical surrogate. It is not guaranteed to obey all physical constraints unless those constraints are explicitly included in the model or evaluation.

Predictions for larger `N` are uncertain because neural networks usually interpolate more reliably than they extrapolate.

The main scientific result should be framed as a test of how well a simple conditional generative model can reproduce and generalize quantum-jump trajectory statistics.
